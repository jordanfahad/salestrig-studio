# SS-002 — Fix LinkedIn multipart video upload
Mode: repo            (code on a branch)
Branch: codex/SS-002
Output: code on the branch; handoff `.agent-bus/outbox/SS-002.md`

## Goal

LinkedIn videos scheduled from Salestrig Studio are uploaded the wrong way. The code cuts the file into fixed 2 MB pieces and sends every piece to the first upload URL LinkedIn returns. It ignores the byte ranges and extra URLs LinkedIn gives, and finalises with an empty upload token. Videos that need more than one part are therefore at risk of failing for every client, on personal profiles and company pages alike. Fix the uploader so it follows LinkedIn's instructions exactly. No new scopes, no reconnect, no schema change.

## What to build

1. In `linkedin.provider.ts`, video path only:
   - Read `uploadToken` from the initializeUpload response.
   - Validate `uploadInstructions` before sending anything: non-empty; each has a URL and integer `firstByte`/`lastByte`; ranges start at 0, are contiguous with no gaps or overlaps, are in order, and the last `lastByte` equals file length minus 1. On failure throw a clear error and do not upload, finalise or post.
   - For each instruction in order, PUT exactly `picture.subarray(firstByte, lastByte + 1)` to that instruction's own `uploadUrl`, same headers as today.
   - Collect each part's `etag` header. If any part fails or returns no ETag, throw before finalising.
   - Finalise with `video`, the real `uploadToken` (an empty string only if LinkedIn returned none, which must be covered by a test), and the ETags in instruction order.
   - Keep `waitForMediaToBeReady` after finalise, unchanged.
2. If it keeps the code testable, extract the range validation and part plan into a small pure function in the same directory (e.g. `linkedin.video-upload.ts`) and list it in the handoff. No other new files except tests.
3. Do not touch the image and PDF single-PUT path except to keep it working.
4. Tests (new):
   - `libraries/nestjs-libraries/src/integrations/social/linkedin.upload.salestrig.spec.ts`
   - `libraries/nestjs-libraries/src/integrations/social/linkedin.page.upload.salestrig.spec.ts`

   Use synthetic `Buffer`s and mocked `fetch`/timers. No network, credentials or database. Cover: one instruction; several instructions with different URLs; part sizes not equal to 2 MiB; the exact final byte; non-empty uploadToken passed to finalise; missing uploadToken; gap, overlap, out-of-order and out-of-bounds instructions rejected before any PUT; missing ETag; a failed part stops before finalise; ETag order; personal (`urn:li:person:`) and page (`urn:li:organization:`) owner; image and PDF over 2 MiB still sent as one PUT.
